## Behavior Implemented

- **Structure (local state, not routes):** top segmented tabs Request Petty Cash / Reimburse Petty Cash / Settle Petty Cash. Request sub-tabs: Petty Cash Request (create) / Edit Petty Cash / History. Reimburse sub-tabs: Reimburse Petty Cash Request / Petty Cash Listing / Edit / History. Defaults: `request` → `create`, `reimburse` → `request`.
- **Shared filter:** one `RecordFilter` state is shared by every listing (Request Edit/History, Reimburse Listing/Edit/History, Settle) and survives top-tab switches while the screen stays mounted; `request` kind on Edit/Listing/Settle, `history` kind on History. `pcMatch` = substring over id/employee/dept/status/action/by/note/purpose plus exact dept/status matching only when the row has those fields.
- **Settle ignores the filter:** the filter is rendered but `settleRows` is passed through unfiltered.
- **Literal tab counts:** Editable 3, History 3, Pending 2 / All 134, To settle 2 / All 58 — never derived, never filtered. Tabs are visual-only (existing `TabbedTable`).
- **Fixtures (exact):** Reimburse listing `PCR-0421/0420/0419`; Edit `PCR-0421/0420/0417`; History `Apr 28/27/25`; Settle `PCF-0210/0208/0205` with literal statuses `To settle`/`Settled` (including the `0.000`-balance row still `To settle`).
- **Request form (create mode):** collapsible "Request N" cards (Location, Zone, Department, Supplier, Year, Amount, Remarks, Attachments), department and KWD chips in the card header, remove only when more than one, "Add another request", live KWD amount preview (`KWD 0.000`, `en-US` three decimals), Summary card (`N request(s)`, Total amount), Actions card.
- **Reimburse form:** same shell with Location, Zone, Department, Year, Activity, Sub Activity, Budgeted Yes/No, Amount, Invoice #, Supplier; Sub Activity falls back to every active sub-activity when no activity (or none) is chosen; changing Activity does **not** reset Sub Activity (the stale value is kept in state and its select shows the placeholder while no matching option exists); "Total Petty Cash" summary; "Submit reimbursement".
- **Submit:** gated only by non-empty attachment captions (red caption border + 3 s error flash with bolt icon); an empty form submits successfully with a 2.8 s success flash (singular/plural copy). Timers are not cancelled, exactly as in the prototype. Nothing is persisted or reset.
- **Row actions:** Reimburse Listing "Reimburse Request" only switches to the Reimburse Request sub-tab (no prefill). Edit (both Edit tables) and Settle Request have no handler.

## Deviations

- **Dead branches not ported (human decision, Option A):** `PettyCashRequestForm` is create-mode only; `review`/`resubmit`/`verify`/`onDecision` are recorded as prototype source-only/dead behavior and the question is preserved for M10.1 (see `DECISIONS.md`).
- **Table tab labels translated:** `Editable`/`Pending`/`To settle`/`All` are plain English strings in the prototype (`TabbedTable` does not call `T`). They are translated here, following M6.6's `allTab` precedent for chrome; row data values stay literal English (established convention).
- **Responsive reflow:** at 760/390 px the prototype's fixed three-column field grid and `1.7fr 1fr` split do not reflow (fields collapse to a few characters). Production stacks to one column below the `tablet` breakpoint, the same approach M6.6's Action Sheet form took. Summary/Actions stay sticky only at tablet width and above.
- **RTL chevrons:** the collapsed card chevron mirrors in RTL; the prototype has no RTL handling.
- **Timer cleanup:** flash timers are intentionally untracked (matches the prototype, including an early clear when two submits overlap).
- **Incidental TabbedTable state:** the prototype's `TabbedTable` active-tab state can survive sub-tab switches (same element position), which leaves no tab highlighted when it carries `pending` into a view that lacks it. Not reproduced (each view owns a fresh `TabbedTable`); it is a purely incidental reconciliation side effect, not authored behavior.
- **Feature-local reuse:** Petty Cash reuses M6.6's `ACTION_SHEET_LOCATIONS/ZONES/DEPARTMENTS/YEARS/SUPPLIERS` constants, which are the identical literals duplicated in the prototype's petty-cash forms.
