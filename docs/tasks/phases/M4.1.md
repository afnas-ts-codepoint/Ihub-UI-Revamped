Direct inspection of the rendered `MasterListingMock` found real, functioning prototype behavior that the M4.1 phase card and the Phase 3 migration plan undersold or omitted entirely. 2. **Bulk row selection.** The prototype has per-row/select-all checkboxes and a bulk Active/Inactive/Delete-all action bar with real local-state mutation — absent from every governing document. **ADOPTED** in full, built on the table engine's row-selection feature (page-scoped select-all, matching the prototype's `toggleAll` operating on the current page only).
3. **Page-level "Add {title}" button.** Opens `MasterAddModal` → `MasterRecordForm`, M4.2 scope, and isn't in the M4.1 task card's scope list. **Rendered inert** (`PROTOTYPE-NOOP(D2)`), preserving the M4.1/M4.2 boundary.
4. **Row View/Edit actions.** Open `MasterViewModal`/`MasterEditModal` → `MasterRecordForm`, also M4.2 scope. **Rendered inert** (`PROTOTYPE-NOOP(D2)`); only Delete is functional in M4.1.

A fifth, non-blocking fidelity detail was found and preserved exactly rather than "fixed": for the **generic mode (Machine Master) only**, the filter dialog's Location/Zone/Created On/Last Updated On/Created By/Last Updated By fields update filter state and the applied-filter badge, but no clause in the row-filter chain ever reads them — only Status (via the shared chip) actually filters generic-mode rows. Registered as `PROTOTYPE-NOOP(D2)`.

A visual-QA pass (see below) additionally surfaced two implementation gaps against the shared prototype `PageHeader` convention, fixed before evidence capture: the page title didn't apply the shared "final word in accent italic" treatment, and `MasterPendingPage` had grown an extra eyebrow paragraph `PageHeader` doesn't render. ## Table engine

`@tanstack/react-table@9.2.4` (current major at intake time; no version was pinned by any governing document, and intake found no conflict). v9 is a feature-registration architecture (`tableFeatures`, `useTable`, `createColumnHelper`) rather than v8's `useReactTable`/`getCoreRowModel()` option style. `shared/table/dataTable.ts` registers exactly the features Masters uses: `columnVisibilityFeature`, `rowSelectionFeature`, `rowPaginationFeature` + `createPaginatedRowModel()`. No sorting, global-filter, or grouping feature is registered — search/status/mode filters are applied by the feature (`filterMasterRows`) before the already-filtered rows ever reach the table.

## DataTableView

`shared/table/DataTableView.tsx` — headless-to-DOM rendering only (`<thead>`/`<tbody>` from `table.getHeaderGroups()`/`table.getRowModel()` via `table.FlexRender`), plus an optional per-row class-name callback (used for the selected-row highlight). It owns no Masters business rules, and per-column `meta.headerStyle`/`meta.cellStyle` are the only column-authored styling hooks.

## TablePagination (functional)

`shared/table/TablePaginationBar.tsx` is new and functional, introduced alongside the existing inert `shared/table/TablePagination.tsx` (unchanged, still used by M3 `TabbedTable` screens). Entries picker (10/25/50/100/All, default 10) plus real previous/page-number/next navigation. Page index is stored unclamped (matching the prototype's `page` state) and clamped only for display (`Math.min(pageIndex, totalPages - 1)`), so a stale deep page is remembered and restored if filtering later reopens it — exactly mirroring the prototype's `curPage = Math.min(page, totalPages)` pattern rather than tanstack's default auto-reset-to-0 behavior (`autoResetPageIndex: false` is set explicitly).

## Search

Single field: `row.name`, case-insensitive, partial match, for all five modes (every seed-row shape carries a `name` field). Whitespace-only search matches everything, matching the prototype's `!search || name.includes(search.trim())` exactly (only a fully empty string short-circuits). No result state is a genuinely empty `<tbody>` — the prototype has no "no results" placeholder for Masters, so none was added.

## Status chips

All / Active / Inactive, with literal counts derived from `allRows` (not the filtered set). "All" resets the chip filter; clicking the active chip again also resets to "all" (toggle-off), matching `onClick: () => setStatus(on ? 'all' : id)`.

## Status toggle

Clicking a row's Status chip flips that row's status locally (`active` ⇄ `inactive`), with no confirmation. Counts and filtered results recompute immediately since they're derived from the same `allRows` state.

## TableToolbar

`shared/table/TableToolbar.tsx` — generic search + middle (chips) + end (action buttons) slots and the card-styled wrapper. Owns no Masters semantics.

## ColumnSettingsDialog

`shared/table/ColumnSettingsDialog.tsx` — three tabs (Chip/Filter/Column Settings), each with Select All / Deselect All and a checkbox-card grid, committed only on Save. The active tab and every tab's draft reset to the committed value each time the dialog opens (matching `openSettings()` always jumping back to the Chip Settings tab), done as a render-time state adjustment rather than an effect (avoids the extra render pass a `useEffect`-based reset would cause, and satisfies this repo's `react-hooks/set-state-in-effect` lint rule).

## Column visibility

Driven directly by tanstack's `columnVisibility` state; the settings dialog's Columns tab lists exactly `definition.columns` (mode fields + Status). The `#`/select/actions columns are structural (`enableHiding: false`) and never appear in Settings, matching the prototype's `allCols` (which also excludes them).

## Chip visibility

Independent of column visibility and of the status *filter* itself — hiding a chip in Settings only stops it rendering in the toolbar; it doesn't clear or reset the active status filter.

## Filter-field visibility

Independent of the underlying filter value: hiding a field in Settings only removes its control from the filter dialog. A value already set on a hidden field keeps filtering (verified directly for the generic mode's inert fields, and structurally true for every mode since `filterMasterRows` never consults visibility).

## Select All / Deselect All

Present in every Settings tab (chips/filters/columns); tested for all three.
