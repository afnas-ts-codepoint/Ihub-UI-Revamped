## Delivered behavior

### View

Every one of the five real Master modes opens a shared, definition-driven View dialog. Values and field order come from the selected row; controls are rendered as read-only text/chips rather than editable inputs. Created On and Status are shown as prototype metadata. Close, header close, Escape and the dialog overlay follow the existing shared Dialog behavior; View does not mutate listing state.

### Edit

Every mode opens a prefilled Edit dialog. `masterFormDraft` maps source rows to form values, including prototype comma splitting for Task Mapping multi-values. Required fields independently gate Save through `masterFormMissing`; the Yup schema validates the same mode-owned fields without adding visible error UI. A valid Save uses `masterFormOutput`, preserves unaffected row fields/code/status, joins Task Mapping arrays with the prototype delimiter and updates the local M4.1 listing. Cancel/close leaves the row unchanged.

Existing selected values absent from the current option list are prepended for Edit display, matching the prototype rather than blanking source data.

### Four specialized Add dialogs

1. Project Category: one initial repeatable Name row; Add more/remove; visible Sample CSV and Upload records controls remain inert for M4.3.
2. Assignment Areas: Location, narrowed Zone and repeatable Area Name/Snag Type rows.
3. Task Mapping: multi-select chip controls for Location/Zone/Area/Sub Area/Matrix list, single selects, severity swatches, Low/Medium/High priority radio with Medium default, and the adopted Sub Area note.
4. Sub Area: Location, narrowed Zone, Assignment Area and repeatable Sub Area names; visible Upload Excel remains inert for M4.3.

### Generic multi-row Add

All non-specialized definitions use the prototype generic mapping form. It starts with one row and exposes Add another row. Each row contains Area, Sub Area, Touch Point, Owner Department, Matrix, Severity, Priority and Guest KPI; Location and Zone sit above the rows. The current prototype does not expose a generic row-removal control, so none was invented. Every row's Area and Department plus Location and Zone gate Save.

### Add result / D2

A valid specialized or generic Add closes the dialog and does not append a row. The listing therefore does not gain the entered record. This intentional prototype behavior is registered as active `PROTOTYPE-NOOP(D2)`; no local persistence, API or fake backend was added.

### Required fields, Yup and submit gating

- `domain/requiredFields.ts` owns the exact mode-specific required-field map and pure `masterFormMissing` rule.
- `schemas/masterRecord.schema.ts` reuses Yup and M3.8's `requiredText` helper.
- Submit-disabled state is computed from the prototype rule, not inferred from `formState.isValid`.
- Golden tests cover a complete fixture, every required field individually missing, combinations, whitespace/null-like reachable values and optional fields for every mode.
- Add-mode tests independently cover initial disabled state, required filling, valid submit and close-only behavior for all four specialized dialogs and generic Add.

### Edit flattening

`splitMasterMultiValue` preserves prototype comma splitting, per-item trimming and empty-fragment removal. `masterFormDraft` flattens scalar Task Mapping row strings into chip arrays; `masterFormOutput` joins arrays back with `, ` and uses the first Area as the saved row name. Golden tests cover representative unusual spacing and round trips for every mode.

### Location → Zone cascade

The rule stays feature-owned in `domain/zonesForLocation.ts` and `data/seedRows.ts`. With no location, all fixture zones are available. Selecting one location narrows to exactly its zones; Task Mapping unions zones for multiple locations with stable de-duplication. Changing location clears a single-select Zone or removes only incompatible Task Mapping zones. Tests cover every prototype location/zone mapping and incompatible-zone retention/removal.

### Task Mapping controls

- `MultiSelectChips` reuses the existing Chip system, supports toggle/remove/clear/wrapping and exposes selected counts.
- Severity uses shared `SwatchRadio`; Low/Medium/High labels make selection accessible beyond color, selected state is exposed with `aria-checked`, and arrow keys rove/select.
- Priority uses shared `SegmentedRadio` backed by native radios; Medium is the Add default and native keyboard behavior is tested.
- Option values, ordering, color mapping, defaults and business meaning remain Masters-owned.
