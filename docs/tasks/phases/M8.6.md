## Review Findings

- Delta intake is clean: prototype `index.html` is unchanged from baseline `273abc8` at current HEAD `3c391b4`.
- The action bar renders exactly six controls in order — CEO Comments, Submit, Approve, Reject, Close Task, More — with the overflow menu (Redirect, Log Note, Export, Print) in that order; only Submit/Log Note/Export/Print are inert toasts, matching the prototype's `flashLocal` fallback.
- The migration plan's "Reject and Close (remarks up to 500 characters, with a counter)" bullet is, in the actual rendered source, two independently-triggered dialogs ("Reject Job Order" and "Close Task") that happen to share the same 500-char-cap/counter/required pattern — not one combined dialog. Implemented as two dialogs sharing one internal `RemarksDialog` helper, which is the faithful reading of the source.
- Approve, Reject, and Close Task are all confirmation-only: each closes and shows a toast with **no task stage/status mutation** anywhere. Redirect and Add Dependency are the two dialogs that mutate real, visible page state (Assignment Info card; Dependencies panel list, respectively).
- The Resolution Tasks ("Update Sub Tasks") dialog is reachable two ways — the header's own standalone toolbar button, and any Sub Tasks Progress row click in edit mode (`openStCard`) — both open the exact same unfiltered dialog regardless of which row was clicked; this exactly matches the source (`openStCard` takes no row argument). Weight-sum validation blocks "Save & Update" above 100% with a persistent banner; "Save as Draft" has no such check. Grouping ("View By: Dept/Assignee") is a genuine quirk: "Dept" mode does not group by each row's own department — it shows one single group labelled with the *parent task's* department, while "Assignee" mode groups by each row's real assignee.
- CEO Comments' "Process owner and assignee are required" footer note is confirmed copy-pasted from Redirect (the dialog has no such fields) and enforces nothing; Save always succeeds. Consistent with the already-approved D2 no-op the task card itself calls out.
- Add Dependency's "Impacted Date" field is conditionally shown only when "Mark as Showstopper" is checked, but is never actually required by validation (only Category + Lead Time gate the Add action) — a newly-found unenforced-requirement quirk of the same shape as the CEO note; recorded as its own `PROTOTYPE_NOOPS.md` row.
- The dead legacy `TaskDetailPage` (a separate, unrelated fallback component with its own `subTaskHistoryModal`) was confirmed unreachable and excluded, matching the standing dead-code rule.
- M8.1's List/Board/in-place modal, M8.2's dashboard, M8.3's Create Task, M8.4's read-only Task View, and M8.5's cards/comments/notes/history/SLA/reminder all remain unchanged and pass their existing regression tests unmodified except the one M8.5 assertion that explicitly asserted the (then-absent) M8.6 controls, which now asserts their presence instead.

## Deviations

No new architectural/product deviation. All prototype quirks (mismatched Approve/Reject/Close copy, the CEO note, the unenforced Impacted Date, the static "Total: 100%" labels, the "Dept" view's single fake group, Copy/Move's inert selection) are preserved verbatim rather than "fixed" — recorded in `PROTOTYPE_NOOPS.md`/this card's Review Findings rather than as deviations, since nothing here diverges from the rendered prototype's actual behavior.

Two implementation-necessary choices where evidence ran out before a pixel-exact answer, both low-risk and reversible:
- CEO Comments' file-dropzone helper copy reuses the existing `edit.uploadNote`/`edit.uploadPrompt` i18n strings (already an approved, tested translation of essentially the same "allowed formats / 2 MB" copy used elsewhere on this same page) rather than transcribing the prototype's slightly-differently-worded note, whose exact Arabic text was not captured during investigation.
- The Resolution Tasks row list does not have a per-row inline weight input in the prototype (confirmed by investigation) — weight is only editable via the Add/Edit Subtask form's "Weight (%)" dropdown (`WEIGHT_OPTS`), which is exactly how this was implemented.
