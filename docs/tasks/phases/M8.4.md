## Objective

Migrate the prototype's `TaskEditPage` rendered `readOnly:true` (exported as `TaskViewPage`) as a real, independently-reachable `/tasks/:taskId` route: a read-only, full-page Task View with its header, all its panels, the Sub Task History dialog (Timeline Log + Gantt), the dependency reminder, and a not-found state for unknown ids — then complete the Phase 3 gates and stop for explicit human approval.

## Scope

- `/tasks/:taskId` route replacing the `PendingRoutePage` placeholder, wrapped in the existing `HomeBannerLayout`.
- Header card: subject, Internal/External chip, SLA status chip, four seeded header stats, inert search box, 8-stage progress track with its two fixed `StageMarkerBadge` popovers, Work Progress %, Started/Target dates, Assigned Users avatar stack with popover, expand button.
- Left-column panels: Sub Tasks Progress (department/sub-department filters, grouped cards), Task Details, Task Classification, Requester Info, Location & Zone (bundled with Asset Category/Name/Code), Activity History (drag-reorderable columns, expandable rows, pagination, inert Filters/Export History PDF).
- Right-column panels: Assignment Info, Dependencies (+ immediate reminder), Reference Numbers, Log Notes, SLA & Performance, Attachments (view + download-toast).
- Sub Task History dialog: Timeline Log tab (search, advanced filters, expandable per-subtask timeline) and Gantt Chart tab (Day/Week/Month toggle, `GanttChart`, stats row).
- Dependency reminder: fires immediately (0ms) in this always-read-only page; "View dependencies" scrolls to/opens/highlights the Dependencies panel.
- Edit Task button: navigates to the still-pending `/tasks/:taskId/edit` route (not implemented here).
- Not-found state for a `taskId` absent from the tasks store.
- New shared modules: `shared/lib/date/workdays.ts` (working days, Fri-Sat weekend) and `shared/ui/charts/GanttChart.tsx`, per the Phase 2 target architecture's pre-approved locations.
- EN/AR, RTL, and the `≤760px` responsive collapse (2-column → 1-column; stage track wraps).

- Do not change M8.1's `TaskDetailDialog`/`TasksPage.tsx` row/card click handlers or make them navigate to this route.

- Do not commit or push.

## Acceptance Criteria

- `/tasks/:taskId` resolves to the new Task View page for both seeded (`TASKS`) and M8.3-created tasks, looked up through the existing `useTask` hook; an unknown id renders a dedicated not-found state instead of a crash or the pending placeholder.
- Every panel listed in Scope renders with the exact prototype content/order for the `readOnly:true` path; no edit-only affordance (action bar, Add Dependency, Update Sub Tasks, Post Comment, attachment upload, SLA edit) is rendered.
- The task's own id is never rendered as visible text on the page.
- The Sub Task History dialog opens from the header expand button and from any Sub Tasks Progress row, with working Timeline Log and Gantt Chart tabs.
- The dependency reminder opens automatically on mount (0ms delay) whenever a dependency is due within 5 working days or overdue, using real Fri-Sat working-days math; "View dependencies" scrolls to and briefly highlights the Dependencies panel.
- Edit Task navigates to `/tasks/:taskId/edit` (still the existing pending placeholder).
- EN/AR render correctly, including the RTL mirrored layout, and the handful of prototype "same-string" no-op labels (see Prototype Verification) are never translated to Arabic.
- G1-G10 pass and the task stops in Review for human approval.

### Preflight result (2026-09-29)

- Prototype HEAD is `3c391b4`, unchanged since the approved baseline `273abc8`; `git diff --exit-code 273abc8 HEAD -- index.html` exited 0 in the prototype repository. No delta intake changes were required.
- Every line reference in the preflight brief was re-verified directly against source during implementation. Findings beyond the brief, all resolved by literal fidelity (see `DECISIONS.md`/`PROTOTYPE_DELTAS.md`/`PROTOTYPE_NOOPS.md` for the full write-ups):
  1. **Log Notes panel is unconditional, not readOnly-gated (non-blocking, literal fidelity).** `logNotesPanel` (`L18770-L18798`) is rendered in the right column in both View and Edit mode; only its compose box is `readOnly ? null : …`. It was not called out in the preflight brief and was ported as its own panel.
  2. **A cluster of visible labels are genuine `T(x, x, locale)` no-ops (non-blocking, literal fidelity).** The header's four stat labels, the 8 stage-track names, the shared `seg()` helper's Day/Week/Month and Log Notes tab options, and the Activity History filter labels all pass the identical string as both the English and Arabic argument to `T()`, so they are never translated to Arabic in the prototype.   3. **Attachment-row `aria-label`s are hardcoded English, not `T()`'d (non-blocking, deliberate a11y choice).** Unlike finding 2, these are screen-reader-only strings, not visible copy; they were translated normally, following this codebase's established convention of translating every feature's aria-labels, rather than preserved as an English-only no-op.
  4. **`TaskViewModel.progress` reused instead of re-deriving the prototype's own seeded progress calc (deviation, recorded as D21).** The prototype recomputes Work Progress from a second, local `checked`/`JO_CHECKLIST` seed independent of any other screen. Task View instead reuses the already-canonical `TaskViewModel.progress` computed once in `tasks.store.ts` (the same figure M8.1's list/board/`TaskDetailDialog` already show), so the same task never shows two different progress percentages across the app.

## Delivered Behavior

### Route and lookup

- `/tasks/:taskId` renders `TaskViewPage`, wrapped by the existing `HomeBannerLayout` (banner with no active tab). `taskId` is resolved through the existing `useTask` hook (seeded `TASKS` merged with M8.3's session-created tasks); a miss renders a not-found state (icon, "Task not found" / "المهمة غير موجودة", short description, and a "Back to tasks" action reusing this codebase's `NotFoundPage` tone rather than the prototype's generic "No task selected." message — see Deviations D22).
- "Back" uses `navigate(-1)` when there is prior history, falling back to `/home/work-centre/tasks` for a direct-link entry (per the Phase 2 target architecture's documented Back behavior).

### Header, panels, dialogs

- All panels/behaviors listed in Scope are implemented per the Prototype Verification section, with the same collapsed/expanded defaults as the prototype's `tepOpenCards` (`subtasks`, `assignment`, and `sla` open by default; every other panel starts collapsed).
- Attachments: the single seeded fixture, metadata-only preview (no real File), and a "Downloading…" toast on Download (no real download) — both match the prototype's placeholder branches exactly.
- Activity History: drag-to-reorder columns, expandable rows, pagination, and the Department/Partner Status/Activity Type filters, all functioning exactly as decoratively as the prototype (the filters never actually filter the row list).
- Dependencies: the single seeded dependency's impact date is computed at render time via `addWorkdays(new Date(), 3)`, matching the prototype's own render-time computation rather than a frozen value.
- Sub Task History dialog: Timeline Log (search + advanced filters + expandable per-subtask timeline, one shared hardcoded timestamp per the prototype) and Gantt Chart (Day/Week/Month toggle over the shared `GanttChart`, decorative cycling-bar positions, stats row).

### No-ops and register updates

See `PROTOTYPE_NOOPS.md` for the full list added by this phase: attachment view/download placeholders, "Export History PDF" being inert, Activity History's three filters being non-functional, the same-string EN/AR labels (stat labels/stage names/Day-Week-Month/Log Notes tabs/Activity History filter labels), Gantt bars being decorative (and having no "today" marker), the Timeline Log's single shared timestamp, and Activity History being static seeded content.

### Localization and architecture

- New `taskView` i18n namespace covers every chrome string; the same-string no-op labels listed above are implemented as literal English constants rather than routed through `t()`, so they cannot accidentally pick up a real Arabic translation.
- `GanttChart` and `shared/lib/date/workdays` are genuinely new shared modules with exactly one real consumer each (the Sub Task History dialog's Gantt tab, and the dependency reminder, respectively), matching the Phase 2 target architecture's pre-approved placement and the "no speculative abstraction" rule.
- Task-View-only fixture data lives in `data/taskView.mock.ts`, feature-local, the same way `tasks.mock.ts` holds `TASKS`/`TASK_CHECKLIST`; the shared `TaskViewModel` type was not expanded.
