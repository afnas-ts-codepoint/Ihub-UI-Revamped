## Review Findings

**Delivered behaviour.**

- `/home/assigned/:queue` (`approvals`, `verify`, `tasks`; any other value is a 404): an underline tab strip with live counts (a tab with a zero count is hidden); Approvals/Verify list the ranked queue in an `ActionList` (Verify captions, drawer opened in verify mode) narrowed by record type, sub-type, priority and search, all in the URL (`type`, `sub`, `priority`, `q`; switching queue keeps priority and search and drops type and sub-type). Type and sub-type options and counts follow the live queue. The `tasks` type lists the external assigned job orders as approve/verify, edit and send-back cards. Assigned Tasks lists every assigned job order as a `JobOrderCard`.
- `/home/incidents/live`: the incident centre (ranked, search, unread and breached-SLA counts, pin, a seven-item Action menu including Close case) beside a sticky live feed of the pinned/tracked incidents and the rejected approvals (dismissable).
- Task form entry points: an Assigned task row or Edit, an Assigned Tasks card click, and an incident's "Raise a task" open the Home task form (D31). `store.openTask` is the entry the Overview (M10.2) will reuse.
- Tracking store: Incident Workspace "Track" now reaches the Home tracker, and a record that is not yet a Home incident opens a pinned "Tracking" incident (visible in the centre and the feed).

**Decision for the reviewer (D31).** The M9.1 recommendation was to send an Assigned task to `/tasks/:taskId`; Home job orders are not in the task store (D16), so that route is a not-found page. Both entry points open the canonical create form in a Home-chrome modal instead. Please confirm or choose another treatment.

**Correction to approved work.** `actionButtonClass('secondary')` (M10.1) was neutral grey; the prototype `.btn.secondary` is blue-outlined. It is now the prototype style, which also restyles the secondary buttons in the M10.1 drawer and batch bar (they now match the prototype).

**Differences seen in the side-by-side evidence (all minor or recorded).** An element-by-element comparison (text size, weight, height; button width and height) of Approvals, Verify, Assigned Tasks and Live Incidents against the new prototype reports no differences.

- Task form body differs from the prototype's full task panel (D31).
- The prototype's searchable select inputs are native selects (D32); the Action menu flips above the button when there is no room below (D32).
- Live feed: the pinned incident's title truncates slightly earlier in the migrated feed.

**Excluded as dead source.** `SheetRow` (13921-14032), the old Assigned "sheets" tab.

**Preserved prototype quirks.** See the five M10.3 rows in `PROTOTYPE_NOOPS.md`; also the stale drawer snapshot and the English-only data text (statuses, SLA labels, feed text, raw priority/status chips).
