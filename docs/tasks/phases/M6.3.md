## Delivered Behavior

### Route map and shell integration

- `/home/purchasing` and `/home/purchasing/create` render the same Purchase Committee Request builder; the default path does not redirect (prototype default `reqSub` state is literally `'create'`, verified at `index.html:10124`).
- `/home/purchasing/pending`, `/edit`, `/review`, `/todo`, `/missing`, `/history`, `/report` render their respective segments.
- Invalid section slugs render the approved 404 page.
- The 8-item segment pill bar mirrors `reqSegBar`'s exact prototype order and literal labels; each `Link` exposes the active section via `aria-current` and supports normal browser Back navigation.
- The prototype's outer 4-tab `pcSub` switcher (`Requests` / `Review Purchase Requests` / `Purchase Order` / `Supplier Quotations`) is intentionally not reproduced as a separate wrapping strip: two of its four tabs (`Purchase Order`, `Supplier Quotations`) lead to explicitly out-of-scope M6.4/M6.5 screens, and building a decorative tab strip pointing at unbuilt functionality would run against G8. The segment pill bar alone carries the reconciled `review` behavior.

### Request segments

- `create` (`PCRequestCreate`): Location/Zone/Department/Year/Activity/Sub-Activity selects, Budgeted yes/no segmented toggle with a derived budget-availability display (via the local `activityBudget` helpers), Location-Type segmented toggle, Remarks, captioned-attachment upload (submit blocked with the literal error until every attachment has a caption), Log Note, multi-request "Combine PC request" building with a running total, and a Submit button that shows a temporary confirmation message (`PC request submitted` / `Combined PC request submitted`) with no persistence, navigation, or row insertion — matching the M6.2 "prototype-local confirmation only" precedent.
- `pending`, `missing`, `history`: `SectionHead` + `RecordFilter` (`kind="request"`, history uses `kind="history"`) + `TabbedTable` against the verbatim-ported fixtures (`purchaseRequestRows`, 4 rows; `missingDocumentRows`, 3 rows; `purchaseHistoryRows`, 3 rows) — exact ids, titles, vendors, values, dates, statuses, tones, missing-doc chips, and days-pending values.
- `edit`: listing using `purchaseRequestColumns` + an inert Edit action column (`PROTOTYPE-NOOP(D2)`).
- `todo`: the fall-through `else` branch — no `SectionHead`, `RecordFilter` + `TabbedTable` with `To Do` (2) / `Record Listing` (88) tabs and base columns.
- `report`: permanent inert placeholder (`RecordFilter` + dashed-border "Run the report to generate results" message), matching the M3.9/M6.1/M6.2 precedent — no chart, no table.
- `review`: the reconciled functional view — `SectionHead` ("Review Purchase Requests" / "مراجعة طلبات الشراء"), `RecordFilter`, and `TabbedTable` with translated `revCols`-equivalent columns (id/title/department/vendor/quotes/value/submitted/status) and a real "Review" action opening `ReviewDialog`.

### Row-filter domain

- `src/features/purchasing/domain/pcMatchRow.ts` implements `pcMatchRow`/`pcRowsF` against a structurally-permissive `PcMatchableRow` type (all fields optional), matching the prototype's dynamic/duck-typed behavior across PC-request, missing-doc, and history row shapes.
- Semantics ported verbatim from `index.html:10203-10211`: case-insensitive, trimmed substring search across `[id, title, vendor, supplier, dept, status, action, by, pcRef, ref]` (absent fields excluded via `.filter(Boolean)`); `dept`/`status` apply only when **both** the filter value and the row field are truthy (a row missing the field passes regardless of the filter value).
- 12 unit tests in `pcMatchRow.test.ts` cover: empty filter, case-insensitive/trimmed search, punctuation-bearing ids (`PC-2025-088`), no-match exclusion, dept exact-match, status exact-match, the dept/status "row has no field" edge case (both directions), history-row matching, combined filters, and the "field absent from haystack" case.

### Review dialog and single-submit supplier lock

- `ReviewDialog` reproduces `revModal` verbatim: tone chip, request title, id/vendor/dept/submitted line, close control, value/KWD display, a 4-cell stat grid (quotations received, lowest/highest quote, committee status) sourced from `revExtra` (all 4 PC ids' full detail ported verbatim), a read-only "Submitted request" grid, Justification paragraph, Attachments list (non-interactive), Committee remarks paragraph, and the awarded-supplier control block.
- `revSupplier`/`revMsg` equivalent state is local to `ReviewDialog`, which is only mounted while its row is selected — every open (including re-opening the same row) is therefore a fresh mount with `useState('')`, which is behaviorally equivalent to the prototype's `useEffect(() => { setRevSupplier(''); setRevMsg(''); }, [revSel, revOpen])` reset.
- The supplier `<select>` is disabled once `message` is set; the submit button is disabled until a supplier is chosen and remains disabled once locked; submitting sets a literal confirmation string embedding the chosen supplier name. No row mutation, listing update, or persistence occurs on close — matching the established prototype-local, no-persistence convention.
- 9 dedicated tests in `HomePurchasingPage.test.tsx` cover: (a) blank/unlocked on open, (b) submit disabled until a supplier is chosen, (c) lock on submit with the confirmation text, (d) select disabled and resubmission a no-op after lock, (e) reset to unlocked/blank on close-and-reopen of the same row, and reset on opening a different row.

### Localization and architecture

- New `purchasing` EN/AR i18n namespace, registered in `i18n.ts`'s `ns` array and `app/i18n.d.ts`'s resource typing; EN/AR key parity is asserted in `i18n.test.ts`.
- Following the established D20-style precedent (also present in `budgeting.json`'s `pagination`/`empty` keys), table/tab column headers and pagination/empty-state strings for the Pending/Edit/Missing/History/To Do segments stay literal English in both locales — matching the prototype's own unwrapped string literals (only `revCols`, the functional Review view, and every heading/pill/button/create-form string are translated, exactly as read from source).
